HOW TO RUN — Paytriq (7-agent campus sponsorship mesh)
=====================================================
Backend: FastAPI (api/). Frontend: dependency-free console (frontend/).
Single service: the API also serves the frontend at / when mounted.

1. PREREQUISITES
---------------
- Python 3.11-3.13 (repo requires >=3.11,<3.14; tested here on 3.13.2).
  Check:  python --version
- No Node/npm needed. No build step for the frontend.
- Optional for full model reasoning:
  - Gemini key (free tier): https://aistudio.google.com/apikey
  - Local Clef decision model (optional, offline): llama-server with Clef-Flash GGUF on port 18781.
  Without both, the system still runs and degrades honestly to the
  deterministic `rules` backend (every FALLBACK is labelled in the trace).

2. INSTALL
----------
From the repo root (this folder):

  pip install -e .[dev]

That installs runtime + test/lint tools (pytest, ruff, mypy).
Runtime-only alternative:

  pip install -r requirements.txt

3. ENVIRONMENT SETUP
--------------------
  Copy the template:

    Windows (PowerShell):  Copy-Item .env.example .env
    macOS/Linux:           cp .env.example .env

  Edit .env. Minimum for a live demo:

    GEMINI_API_KEY=<your key>        # enables model-driven decisions; without it all decisions read FALLBACK
    GEMINI_MODEL=gemini-3.5-flash-lite
    DECISION_BACKEND=gemini          # pinned for demo machines/Render (no local GPU needed)
    HUMAN_GATES_INTERACTIVE=true     # gates block for a human (correct for the evaluated demo)
    TOOLS_LIVE=false                 # fixture-backed tools, labelled as fixtures (default, safe)

  Nothing in .env is required to boot. A blank .env still runs (rules + fixtures).

4. START THE BACKEND
--------------------
From the repo root:

  uvicorn api.main:app --reload --port 18780

Alternative (same thing):

  python -m api.main

The server prints the run id on startup. Leave it running.

Verify it is up (browser or curl):

  http://localhost:18780/healthz        -> {"status":"ok",...} (liveness, touches nothing)
  http://localhost:18780/health         -> per-subsystem readiness (decision chain, tools, runs)
  http://localhost:18780/docs           -> interactive API docs
  http://localhost:18780/openapi.json   -> machine-readable contract
  http://localhost:18780/               -> service index (JSON) + frontend if mounted

Default port is 18780. If PORT is set (Render/Heroku inject it), the server honours it.

5. OPEN THE FRONTEND (pick one)
-------------------------------
A) Served by the backend (recommended, no CORS issues):
     http://localhost:18780/
   (api/main.py mounts frontend/ at / when frontend/index.html exists.)

B) Direct file open:
     Double-click frontend/index.html (works from file://).
     Set "API base" in the header to http://localhost:18780 and press Apply / reconnect.

The header shows API base, run_id, and a health strip. If the backend is down,
a pinned banner names the URL tried and the start command.

6A. GUIDED DEMO — ONE CLICK (use for the evaluated live demo)
-------------------------------------------------------------
In the console, top strip ("guided demo bar"):

  1. Press "Run full demo".
     Calls POST /api/demo/run with the prefilled TechFest 2026 event.
     Runs discover -> propose -> outreach -> reply -> contract -> compliance -> audit
     in one call. SEND/MOU gates are approved as decided_by="demo-auto"
     through the normal approval write path (they read as auto, never human).

  2. Watch "Live trace" (centre) + handoff chain (A1 -> A2 -> ...).
  3. Press "Refresh" in "Run summary" (or it refreshes automatically).
     Featured number: distinct_gap_values (anti-fabrication timing check).
  4. Toggle "Simple view" to hide the 4 inspector panels during the demo;
     toggle back ("Show all panels") for per-decision drill-down.

Same thing via API (no UI):

  POST http://localhost:18780/api/demo/run
  Content-Type: application/json

  {
    "name": "TechFest 2026",
    "location": "VIT Pune, Karad Road",
    "footfall": 5000,
    "date": "2026-02-14",
    "audience": "Second and third year engineering students",
    "categories_wanted": "cafe, coaching, bookstore, printing",
    "deliverables_offered": "main-stage logo backdrop, expo stall",
    "budget_inr": 150000,
    "contact_email": "events@vit.edu.in"
  }

  Response gives: event_id, run_id, per-stage artefacts, auto_approvals,
  trace (/api/runs/{run_id}/trace), summary (/api/runs/{run_id}/summary),
  stream (/api/runs/{run_id}/stream).

6B. MANUAL DEMO — SEVEN STAGES (use for Section A per-decision evidence)
------------------------------------------------------------------------
  1. Press "Prefill demo event", then "Create event" (POST /api/events).
     run_id is learned automatically; the trace stream opens by itself.
  2. Run "Discover" (A1), then "Propose" (A2). Watch the handoff chain.
  3. "Outreach" (A3) is EXPECTED to be refused: 403 {gated:true}.
     That refusal is the feature. A gate card appears in "Human gates".
     Approve it (approve/reject/revise + instruction), then press Outreach again.
  4. "Reply": pick the "ambiguous" preset
     ("Yesterday we thought the price was too high, but lets proceed.")
     and press "Send reply". The intent card shows the classifier result.
  5. "Contract" (A4) will 403 on the MOU gate the same way. Approve, retry.
  6. "Compliance" (A5, veto authority), then "Audit" (A6, ROI report).
  7. Read "Run summary": distinct_gap_values + raw gaps (recomputable).

  Keys: 1-7 run a stage, n = next unrun stage, f = trace focus mode.

  Manual API equivalents:
    POST /api/events                                   create event
    POST /api/events/{event_id}/discover | propose | reply | compliance | audit
    POST /api/events/{event_id}/outreach?gate_id={gid}  (403 until approved)
    POST /api/events/{event_id}/contract                (403 until approved, body {brand?})
    GET  /api/gates/{run_id}                            outstanding/answered gates
    POST /api/gates/{gate_id}  {"outcome":"approve","decided_by":"<name>","instruction":"..."}
    GET  /api/runs/{run_id}/trace | summary | board | disputes | lessons | handoffs
    GET  /api/runs/{run_id}/stream                      SSE live feed

7. KEY ENDPOINTS CHEAT SHEET
----------------------------
  GET  /health                    readiness (add ?probe=true to dial decision backends; slow)
  GET  /api/schema/event          JSON Schema + valid sample + curl line for the create body
  GET  /api/pipeline/stages       stage list with gate flags (generated from code)
  POST /api/demo/run              one-click full pipeline (demo-auto approvals)
  GET  /api/runs/{run_id}/lint   trace linter (missing sources, dangling refs)

8. RUN THE TESTS
----------------
  Offline suite (default, no keys/network needed):

    python -m pytest -q tests/unit/test_graph.py
    python -m pytest -q tests/unit/test_api.py tests/unit/test_graph.py

  Full suite:

    python -m pytest -q

  Live-model tests are gated (skipped by default):
    pytest --run-live      (needs GEMINI_API_KEY)
    pytest --run-clef      (needs local llama-server on $CLEF_BASE_URL)

  Lint + types:

    ruff check .
    mypy

9. DEPLOY (Render, one service)
-------------------------------
  - render.yaml defines one Docker web service; health check is /healthz.
  - Dockerfile serves API + frontend on $PORT.
  - In the Render dashboard set secrets (never in the file):
      GEMINI_API_KEY, CLEF_ACCOUNT_ID, CLEF_API_KEY, GIT_COMMIT
    Keep HUMAN_GATES_INTERACTIVE=true for the evaluated demo.
  - Keep the Project URL live until results are published. A dead link on
    demo day forfeits Live Demo marks regardless of any recording.

  Docker locally:

    docker build -t paytriq .
    docker run -p 18780:18780 -e GEMINI_API_KEY=<key> paytriq

10. TROUBLESHOOTING
-------------------
  - "Backend unreachable" banner: uvicorn is not running or the API base is wrong.
    Start it (step 4), set API base to http://localhost:18780, Apply/reconnect.
  - Every decision reads FALLBACK/rules: GEMINI_API_KEY is unset and no clef
    server is reachable. The run is still honest, but set the key for
    model-driven evidence (Section A).
  - Outreach/contract 403 {gated:true}: correct behaviour. Approve the gate
    card (or use POST /api/demo/run, which auto-approves as demo-auto).
  - Stage timeout: a full stage can take ~2 min; the console allows 300 s.
    A genuine timeout lands in the banner/stage note, never as silence.
  - Port in use: change --port or set PORT env var.
  - CORS from file://: backend sends Access-Control-Allow-Origin: * (no
    credentials). Under the static mount (same origin) this is a non-issue.
  - Stale panel note ("last sent at ..."): the last refresh failed; the panel
    shows the previous snapshot labelled stale, not current data.
  - traces/ is gitignored; the committed golden run lives in
    docs/samples/golden_run.jsonl + golden_summary.json (provenance in README).

Docs map: docs/SYNOPSIS.md (2-min version), docs/DESIGN.md (architecture +
generated mermaid), docs/INPUT.md + docs/OUTPUT.md (contracts + samples),
docs/EVALUATION.md (ablation manual), frontend/README.md (console manual),
docs/CLEF.md (read first: why a decision model, not a chat LLM).
